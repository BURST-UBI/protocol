## Required phases and ownership

1. Select one eligible archive key through the existing indexed metadata cursor.
   Persist progress only with the work it describes. Bound examined rows and
   copied bytes, including skipped inline/unsupported records. Do not repeatedly
   restart at the beginning or skip an oversized supported record forever.
2. Validate the original logical bytes and canonical head span under a pinned
   read view, with bounded continuation/cancellation. Original descriptor and
   pages remain authoritative throughout preparation. Limit retained input RAM
   and pinned-reader lifetime explicitly; a16MiB record limit alone does not
   bound worker time or copy-on-write growth.
3. Build nodes in bounded writer batches using ordered_radix. A committed
   unfinished forest must have durable ownership. In the same transaction,
   transfer temporary ownership from consumed child roots to each new parent
   and save the new frontier. The frontier has at most257roots. A live in-memory
   builder alone is insufficient:457cleanup can reclaim every zero-owner node.
4. Stage envelope pages using the existing byte format in a migration-specific
   namespace, with a bounded page/byte budget. Persist count/commitment state
   with pages; never expose incomplete envelope bytes through a live descriptor.
   Large certificate/proposal suffixes must work; tests already include these.
5. Verify the complete staged reconstruction, then atomically publish the final
   descriptor and root/envelope ownership only if its source identity is still
   current. A raw descriptor comparison alone has not been proven sufficient:
   existing RecordObservation verifies full logical bytes, and a mutable paged
   value has multiple dependencies. Establish a mutation-complete source token
   or immutable ownership before replacing that verification with a cheap check.
   Do not use unrelated global ledger generations as an automatic restart rule.
6. Retire old pages and staging ownership through bounded persistent cleanup.
   Existing paged_metadata::delete_at and Writer::finish loop through all old
   pages; calling either for a whole large record inside final publication would
   reintroduce the long transaction this migration is intended to avoid.

Every phase must survive abort and reopen. Cancellation cannot publish a partial
record, drop original ownership, leak staging pins permanently or discard the
only cleanup cursor. Stale source inputs abort the migration without replacing
newer bytes. Errors must retain enough durable state for bounded reclamation.

## Checks required before scheduling migration

- Progress across writer boundaries and process restart, including a partially
  completed tree frontier and large envelopes.
- Existing cleanup running between every staging batch cannot reclaim owned
  staging nodes. Abandoned staging eventually releases its pins.
- Abort/cancellation at each publication boundary preserves exact original bytes.
- Replacement/deletion of the source during preparation cannot be overwritten.
- Corrupt descriptors, nodes, pages and continuation state fail closed.
- Every phase enforces explicit node/page/byte budgets, including skip, finish,
  stale cleanup and error paths; no final unbounded scan or deletion loop.
- Pinned readers retain original bytes across publication and cleanup.
- Retained450fixtures provide physical live/extent and write-stage comparisons;
  preserve baseline hashes and reuse456/457functional evidence within scope.
- Measure writer occupancy and sustained progress separately from functional
  count bounds. Debug/validation timing is not release acceptance.
