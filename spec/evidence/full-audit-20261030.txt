## Findings and minimal remediation

### PA06 — reversal hides active-balance overflow (P3, reproduced; now fixed in source)

`trst/src/engine.rs::restore_origins` updates revocation state and attempts an
indexed restoration. An indexed validation error falls back to legacy mutation;
active balance uses saturating addition. The method returns a successful-looking
restoration list even when the restored token sum exceeds u128. Related receive
paths should distinguish “index unavailable” from “index rejected this mutation”
instead of using one boolean/fallback for both conditions.

The test `engine/portfolio.rs::audit_pa06_reversal_overflow_reaches_persistence_guard`
constructs a revoked maximum holding plus a live unit and restores the former.
Both raw and indexed representations expose the overflow. Stable holding-row
persistence and snapshot loading reject the result. Inspected node transitions
use staged engines and durable validation before publication. Counter refresh
alone is not the guard: the active-holding persistence validation is.

No valid signed history reaching this synthetic state, durable corruption or theft
was established. Fix by returning a checked Result and staging graph, holdings,
indexes and outcome changes together; reuse the existing expiry transition's
validate-before-publish approach. Regressions should cover maximum valid totals,
overflow rejection and unchanged whole-engine state on failure. Do not merely
replace saturation with a panic or return after mutating the revocation graph.

### FA01 — wallet backup import lacks an allocation bound (P3 local hardening, reproduced)

`wallet_core/src/keystore.rs::load_keystore` calls `read_to_string` on the entire
selected file before JSON validation. Native `load_keystore_cmd` reaches it.
Unknown JSON fields are ignored. The added
`audit_backup_import_accepts_large_ignored_metadata` accepts over 1 MiB of harmless
padding. This demonstrates no import-size limit; it does not simulate OOM.

A user must open a hostile local backup. Larger files can exhaust memory or stall
import before cryptographic profile checks. The earlier PA05 profile fix remains
valid but does not bound file size or hex-decoded field sizes. No seed theft was
shown. Reuse the bounded offline-import reader pattern; set a documented v1 file
limit and exact/maximum salt, nonce and ciphertext lengths before decoding/KDF.
Test at-limit/over-limit files, oversized fields and existing legitimate backups.
A metadata size check alone is insufficient against a file changed while reading.

### FA02 — decrypted key material is not consistently wiped (P3, source, open)

In `wallet_core/src/keystore.rs`, `derive_key` returns a plain byte array and AES
plaintext remains an ordinary Vec; native unlock/export paths also make seed and
password copies. These buffers have no guaranteed wipe on drop. This increases
residual secret lifetime if process memory is later exposed; no memory-read or
exfiltration attack was demonstrated. Reuse the existing Zeroizing/key wrappers
used by crypto delegation code for temporary keys and plaintext. Minimize copies;
do not claim Rust zeroization can reliably erase JavaScript strings or OS dumps.

### FA03 — BRN forfeiture has partial mutation on error (P3 defensive hardening; now fixed in source)

`brn/src/engine.rs::forfeit_stake` subtracts total_staked before checked addition
to total_burned. If the addition overflows, it returns an error after changing the
wallet while leaving the stake unresolved. This requires inconsistent/extreme
input state; no legitimate accrual history or durable node publication was shown.
Compute both new totals before assigning either, preserving the existing API.
Add one invalid-state atomicity regression and retain normal forfeiture coverage.
This is a small local fix, not a reason to redesign the staking engine.

### FA04 — plain-HTTP membership queries lack transport privacy (policy limitation, source)

`groups/src/client.rs::endpoint_url_checked` accepts HTTP for any host, and
`verify_member` includes the wallet identifier in the URL path. Registry and wallet
policy validation reuse/allow that scheme. An on-path party can observe queries
or alter informational membership responses when a selected endpoint uses HTTP.
Scores are explicitly not consensus voting weight. No signature bypass follows.
HTTP public-directory/IPFS retrieval is intentional and discloses no wallet ID;
that does not make authenticated membership transport private.

The subsequent design/reference check found simple REST and HTTP(S) acceptance
consistent with current design, with no established HTTPS-only requirement.
Explain membership disclosure and prefer HTTPS; making remote HTTP impossible
is a policy change, not an automatic defect fix. Directory retrieval and
membership queries disclose different information. Do not silently trust directory
entries or describe plaintext queries as confidential.
No network interception test was run; scheme acceptance and query construction
are directly visible in source.

### Additional bounded hardening (source observations)

* Dashboard `src-tauri/src/commands.rs::read_logs(lines: u32)` buffers journalctl
  output without a byte cap. Arguments are separate process arguments, not shell
  interpolation. Bound line count, streamed bytes and duration. Requires trusted
  local IPC use; no remote command injection was found.
* Release actions include mutable version tags and toolchain action references.
  Pin reviewed action commits and retain an update process. Installer SHA256SUMS
  detect mismatched downloads but share the release publisher's trust boundary;
  they do not authenticate against a compromised publisher. Signed provenance is
  a separate release improvement, not something this audit silently enabled.

## Complexity and resource review

The earlier `OPERATION_COMPLEXITY_AUDIT.md` and decision tables remain the detailed
algorithm inventory. This pass checked that security hardening does not bypass
those mechanisms: fixed-size authentication work; bounded merge/release lists;
indexed holdings and provenance dependencies; global BRN rate history rather than
per-wallet rewrites; paged reads and bounded queues; staged rollback and replay.
Work proportional to affected holdings/provenance, electorate tally, snapshot
size or recovery history remains real work, not O(1) merely because it is indexed.
Rate-history access, state retention and background recovery must be evaluated
against their actual state dimensions. No new asymptotic production benchmark or
100+ TPS/subsecond claim is made. FA01 and dashboard log buffering are concrete
remaining allocation boundaries; PA06 shows why fast-path failure must not fall
back into unchecked mutation. No generic caching or parallelism rewrite is justified
by this audit alone.
